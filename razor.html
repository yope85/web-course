    למה? תפריט אחד במקום שישה

    בשיעור 5 הדבקתם את אותו navbar בכל דף. רוצים להוסיף לתפריט קישור? בחרו סוג אתר ולחצו ➕:

    בדפי HTML כל קובץ מחזיק עותק של התפריט – ובטוח שוכחים אחד. עם תבנית התפריט כתוב רק ב-_Layout.cshtml, וכל הדפים מקבלים אותו ממנה. זה מה שהגשה 1 דורשת.
    כמו פעולה ב-C#: קוד שחוזר על עצמו כותבים פעם אחת, וקוראים לו מכל מקום.

    דף Razor: HTML ו-C# בשני קבצים

    דף Razor הוא דף שיש בו HTML וגם C#, וה-C# רץ בשרת – לפני שהדף נשלח לדפדפן. Visual Studio יוצר לכל דף שני קבצים. כך הם נראים בדף ריק בשם About:

    About.cshtml – התצוגה (view): HTML עם C#. כאן כותבים.

    @page
@model MyFirstWeb.Pages.Site.AboutModel
@{
}

    About.cshtml.cs – קוד השרת: מחלקה (class) של C# (מקוצר).

    namespace MyFirstWeb.Pages.Site
{
    public class AboutModel : PageModel
    {
        public void OnGet() { }
    }
}

    כותבים רק בקובץ cshtml, ואת שלוש השורות שבראשו לא מוחקים:

    • @page – "אני דף, ויש לי כתובת".
    • @model – מחבר את הדף למחלקה AboutModel שבקובץ About.cshtml.cs. במקום MyFirstWeb יופיע שם הפרויקט שלכם.
    • @{ } – בלוק ריק של C#, נמלא אותו בהמשך.
    
      
    📄❓
    This localhost page can’t be found
    HTTP ERROR 404
    
      
    בלי @page הקובץ כבר לא דף – אין לו כתובת, והשרת עונה 404 ("לא נמצא").
    
    
    
    
    הקובץ cs הוא מחלקה רגילה של C#, ובה הפעולה OnGet – היא רצה בכל פעם שמישהו פותח את הדף. בהמשך השנה תכתבו בה קוד.
    
    
    דף חדש בהעתקה של קובץ (Copy, Paste)? בשני הקבצים תהיה מחלקה באותו שם – שגיאה. דף חדש יוצרים תמיד דרך Add ‏←‏ Razor Page.
    
  
    

  
    
    
    @ – מכאן מתחיל C#
    
    
    בתוך ה-HTML, התו @ אומר ל-Razor: "מכאן זה C#". השרת מריץ את הקוד, ובמקומו כותב את התוצאה. הנה About.cshtml עם תוכן:
    
    
    
    
    
      
    About.cshtml – מה שכתבתם
    
      
    מה הדפדפן מקבל (Ctrl+U)
    
      
    מה רואים בדפדפן
    
    
    
    
    
    
    השרת מריץ את ה-C# מחדש בכל טעינה – לכן השעה מתעדכנת. ב-Ctrl+U (קוד המקור) אין אף @ – הדפדפן מקבל HTML רגיל. ועוד שני סימנים: הערה של Razor, @* … *@, נמחקת בשרת ולא נשלחת; וכדי להציג את התו @ עצמו כותבים @@ בדף. (על ~/ – בנושא "כתובות ונתיבים".)
    
    
    כמו Console.WriteLine("Time: " + x) ב-C#: על המסך לא מופיעה האות x – מופיע הערך שלה. כך גם מה שאחרי @.
    
  
    

  
    
    
    ViewData["Title"] – הכותרת בלשונית
    
    
    את הכותרת שבלשונית קובעים בבלוק @{ } – בלוק של פקודות C#, כל אחת עם ; בסוף. כתבו כותרת בתיבה וראו מה קורה:
    
    
    
    
    About.cshtml – הדף שומר את הכותרת
    
    
    
    
    _Layout.cshtml – התבנית (בנושא הבא) קוראת אותה
    
    
    
    
    🌐 
    localhost:7123/Site/About
    
    
    הדף שומר את הכותרת ב-ViewData, והתבנית המשותפת קוראת אותה לתוך התגית title – ואחריה מוסיפה את שם הפרויקט. דף בלי כותרת? בלשונית יופיע רק " - MyFirstWeb".
    
    
    ViewData הוא כמו Dictionary<string, object> ב-C# – או כמו מערך שבו לתא קוראים בשם ("Title") ולא במספר. הדף כותב לתא, והתבנית קוראת ממנו.
    
    
    🚀 להעמקה: למה ב-Ctrl+U הכותרת בעברית נראית כמו קוד מוזר?
      
    כל מה שיוצא מ-@, Razor מקודד (encode) לפני השליחה – כדי שאף אחד לא יוכל "להשתיל" קוד בדף דרך טקסט. כברירת מחדל רק אותיות באנגלית נשארות כמו שהן; כל אות אחרת נכתבת כקוד מספרי. אז ב-Ctrl+U תראו:
    
      
    <title>&#x5D0;&#x5D5;&#x5D3;&#x5D5;&#x5EA; - MyFirstWeb</title>

    
      
    הדפדפן מתרגם את הקודים בחזרה, ובלשונית כתוב "אודות" כרגיל. עברית שכתבתם ישר ב-HTML (לא דרך @) נשלחת כמו שהיא. להרחבה: Microsoft Learn: Cross-site scripting (באנגלית).
    
    
    
  
    

  
    
    
    💻 עכשיו אצלכם ב-Visual Studio

    2. קליק ימני על Site ‏←‏ Add ‏←‏ Razor Page... ‏←‏ בחרו Razor Page - Empty ‏←‏ Add. בשדה השם מופיע Index.cshtml – מחקו וכתבו About (את הסיומת Visual Studio מוסיף לבד) ‏←‏ Add. נוצרו שני קבצים: About.cshtml, ומתחתיו (חץ קטן לידו) About.cshtml.cs. (לא מוצאים Razor Page...? Add ‏←‏ New Item... ‏←‏ Razor Page - Empty. לא אומת)
      3. 
      
    3. ב-About.cshtml השאירו את שתי השורות הראשונות (@page ו-@model). את כל מה שמתחתיהן מחקו, והדביקו במקומו. ב-src כתבו שם של תמונה שיש לכם בתיקייה Img:

<img src="~/Img/pic.jpg" alt="תמונה" width="150" />

    5. 🔨 נסו לשנות: שנו את הכותרת ל-"מי אנחנו", שמרו, לחצו 🔥 Hot Reload בסרגל של Visual Studio (כמו בסרטון – דפי cshtml עוברים הידור, ולכן צריך את הלהבה) ורעננו את הדפדפן – הלשונית השתנתה? חכו דקה ורעננו – השעה התעדכנה? ולבסוף Ctrl+U וחפשו (Ctrl+F) את התו @ – הוא לא שם.

    _Layout.cshtml – מה שמשותף לכל הדפים
    
    
    בתיקייה Pages/Shared יש קובץ ש-Visual Studio יצר: _Layout.cshtml – התבנית. כתוב בו מה שמשותף לכל הדפים: head, תפריט ותחתית (footer).
    
    
    
    
    פתחו דף:
    
    
    
      
    
        
    Pages/Shared/_Layout.cshtml (מקוצר)
    
        
    
      
    
      
    מה רואים בדפדפן
    
        
    סגול מקווקו = התוכן של הדףכל השאר = מ-_Layout
    
    
    
    
    בכל דף התפריט והתחתית זהים – הם מ-_Layout. משתנה רק החלק המקווקו: התוכן של הדף, שנכנס במקום @RenderBody() שבתבנית. (הכול משמאל לימין, כי בתבנית אין dir="rtl" ומקושר Bootstrap הרגיל – תתקנו בשלב 💻.)
    
    
    @RenderBody() הוא כמו קריאה לפעולה שמחזירה את התוכן של הדף: התבנית "קוראת" לה, ובמקום הקריאה נכתב מה שחזר.
    
    
    🚀 להעמקה: מי מחבר בין הדף לתבנית?
      
    שני קבצים קטנים בתיקייה Pages, שגם אותם Visual Studio יצר. Pages/_ViewStart.cshtml רץ לפני כל דף, וקובע שכולם משתמשים בתבנית:
    
      
    @{
    Layout = "_Layout";
}

    
      
    Pages/_ViewImports.cshtml הוא כמו שורות ה-using בראש קובץ C# – אבל לכל הדפים יחד. השורה האחרונה בו מפעילה Tag Helpers – מאפיינים (attributes) כמו asp-page, בנושא הבא:
    
      
    @using MyFirstWeb
@namespace MyFirstWeb.Pages
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers

    
      
    הקו התחתון בתחילת השמות הוא מוסכמה (convention): "זה לא דף שגולשים אליו – זה קובץ שעוזר לדפים אחרים". ובתחתית התבנית יש עוד מקום שדף יכול למלא: @await RenderSectionAsync("Scripts", required: false) – למשל קוד JavaScript שרק הדף הזה צריך, בתוך @section Scripts { … } בדף. להרחבה: Microsoft Learn: Layout in ASP.NET Core (באנגלית).
    
    
    
  
    

  
    
    
    🔨 ומה אם מוחקים את RenderBody?
    
    
    בתבנית יש מקום אחד לתוכן של הדף – השורה @RenderBody() שראיתם. מה יקרה אם נמחק את השורה הזו?
    
    
    
    
    
    
    
    
    
    
    זו הודעת השגיאה האמיתית. בתרגום: "בדף /Pages/Shared/_Layout.cshtml לא קראו ל-RenderBody". השרת לא "בולע" דף בשקט – הוא עוצר ומודיע. בדף שגיאה כזה תמיד כתוב מה הבעיה ובאיזה קובץ – קוראים את השורה הראשונה לפני שמנחשים.
    
  
    

  
    
    
    💻 עכשיו אצלכם ב-Visual Studio
    
    
    מתאימים את התבנית לאתר שלכם: עברית מימין לשמאל, Bootstrap RTL, העיצוב שלכם – והתפריט שלכם, פעם אחת לכל האתר.
    
    
      
      
    1. ב-Solution Explorer פתחו את Pages ‏←‏ Shared ‏←‏ _Layout.cshtml (לחיצה כפולה).
      2. 
      
    2. בשורה 2 שנו את <html lang="en"> ל-<html lang="he" dir="rtl"> – עברית, מימין לשמאל.
      3. 
      
    3. ב-head, בשורה של Bootstrap, שנו את bootstrap.min.css ל-bootstrap.rtl.min.css (מוסיפים rtl – כמו בשיעור 5).
      4. 
      
    4. ב-head יש עוד שתי שורות link: site.css של התבנית, ושורה שבה שם הפרויקט שלכם ו-styles.css – עיצוב של התבנית עצמה. משאירים את שתיהן. אחריהן – לפני </head> – הדביקו את העיצוב שלכם. אחרון = מנצח (שיעור 5):
        
      <link rel="stylesheet" href="~/css/site-style.css" />

      
        (בפרויקט של ‎.NET 9 יש ב-head גם שורה <script type="importmap"></script> – לא נוגעים בה.)
      5. 
      
    5. התפריט: ב-_Layout סמנו את כל ה-header של התבנית – מ-<header> ועד </header> כולל – ומחקו. במקומו הדביקו את ה-navbar שלכם מ-page1.html (שיעור 5), מ-<nav ועד </nav> כולל. (למה בלי header? בתוך header, ה-sticky-top שלכם לא "נדבק" למעלה.) הקישורים בו עוד לא יעבדו – נתקן בנושא הבא.
      6. 
      
    6. צבע הקישורים: ליד _Layout.cshtml (חץ קטן לידו) יש קובץ בשם _Layout.cshtml.css – עיצוב שחל רק על התבנית. פתחו אותו ומחקו ממנו שני כללים: a { color: #0077cc; } – צובע בכחול כל קישור בתפריט, וגובר על כללים כמו .nav-link שלכם; ו-a.navbar-brand { … } – שובר את שם האתר באמצע מילה. את הקובץ עצמו לא מוחקים (אחרת הקובץ styles.css מה-head עלול להיעלם – 404).
      7. 
      
    7. התחתית: ב-footer מחקו את השורה עם &copy; והקישור Privacy, וכתבו במקומה למשל &copy; 2026 - שם האתר שלכם (הקוד &copy; מציג את הסימן ©).
      8. 
      
    8. שמרו (Ctrl+S) והריצו (▶). פתחו את דף הבית, ואז הוסיפו בסוף הכתובת /Site/About ולחצו Enter.
      9. 
    
    
    
    בשני הדפים – הכתובת שמסתיימת ב-/ והכתובת שמסתיימת ב-/Site/About – רואים למעלה את התפריט שלכם, והטקסט מיושר לימין, בגופן ובצבעים מ-site-style.css. התוכן של כל דף שונה, התפריט והתחתית זהים. ברוחב טלפון (F12, ואז Ctrl+Shift+M) כפתור ☰ פותח וסוגר את התפריט.

    איזו כתובת פותחת איזה קובץ?
    
    
    ראיתם שהדף About נפתח בכתובת /Site/About. ודף עמוק יותר?
    
    
    
    
    
      
    
      
    
    
    
    
    
    
    דף Razor: התיקיות שבתוך Pages ושם הדף – בלי Pages ובלי סיומת; השרת מריץ אותו. קובץ ב-wwwroot (תמונה, css, html): עם הסיומת; נשלח כמו שהוא. ודף Index הוא ברירת המחדל: Pages/Index.cshtml נפתח בכתובת / – דף הבית.
    
    
    🚀 להעמקה: מי מחליט על כל זה? Program.cs
      
    בקובץ Program.cs שבפרויקט יש השורות שמפעילות את שני העולמות. app.MapRazorPages() נותן כתובת לכל קובץ ב-Pages שיש בו @page בראש. ומי שולח קבצים מ-wwwroot? בפרויקט של ‎.NET 8 – השורה app.UseStaticFiles(); ובפרויקט של ‎.NET 9 – השורה app.MapStaticAssets(); (שתי דרכים לאותו רעיון). רוצים לבדוק איזה ‎.NET יש לכם? קליק ימני על הפרויקט ‏←‏ Properties ‏←‏ Target framework.
    
    
    
  
    

  
    
    
    asp-page: קישור שהשרת בונה
    
    
    בתפריט של התבנית אין href. זו שורה אמיתית מתוך התבנית, _Layout.cshtml של Visual Studio:
    
    
    <a class="nav-link text-dark" asp-area="" asp-page="/Privacy">Privacy</a>

    
    
    asp-page הוא Tag Helper: מאפיין (attribute) שהשרת קורא – הוא מוצא את הדף ובונה ממנו href. בחרו ערך וראו מה הדפדפן מקבל:
    
    
    
    
    ב-_Layout.cshtml
    
    
    מה הדפדפן מקבל (Ctrl+U)
    
    
    
    
    💡 כותבים תמיד עם / בהתחלה ובלי סיומת, למשל asp-page="/Site/About". ואת asp-area="" שבתבנית אפשר להשאיר או למחוק – לא נשתמש בו.
    
    
    🚀 להעמקה: למה לא פשוט href="/Site/About"?
      
    גם זה עובד. היתרון של asp-page: השרת בונה את הכתובת לפי הדפים שקיימים באמת. אם האתר יעלה פעם לכתובת משנה (למשל /dana/ בשרת של בית הספר), הקישורים יתעדכנו לבד. ובלי / בהתחלה, asp-page מחפש את הדף יחסית לתיקייה של הדף הנוכחי. להרחבה: Microsoft Learn: Anchor Tag Helper (באנגלית).
    
    
    
  
    

  
    
    
    ~/ – נתיב שמתחיל מ-wwwroot
    
    
    בדף About ראיתם שהשרת הופך ~/Img/pic.jpg ל-/Img/pic.jpg – נתיב מהשורש של האתר. אבל בשיעורים 2–3 כתבתם ../Img/pizza.jpg, "עלו תיקייה אחת". זה עדיין עובד?
    
    
    
    
    
      
    הכתובת בדפדפן:
    
      
    בדף כתוב src="…" עם:
    
    
    
    
    
    
    הדפדפן רואה רק את הכתובת, ולפיה מחשב נתיב יחסי. לכן ../Img עובד רק "במזל", בכתובות בעומק תיקייה אחת. ~/ עובד תמיד: השרת הופך אותו לנתיב מהשורש של האתר.
    
    
    נתיב יחסי (relative) תלוי איפה עומדים; נתיב מוחלט (absolute) מתחיל תמיד מאותה נקודה – כמו C:\Users בסייר הקבצים.
    
  
    

  
    
    
    💻 עכשיו אצלכם ב-Visual Studio
    
    
    מתקנים את הקישורים בתפריט שב-_Layout, ומוסיפים קישור לדף "אודות".
    
    
      
      
    1. ב-_Layout.cshtml, בתפריט שלכם, החליפו כל href="....html" ב-asp-page לפי הטבלה. את דפי התוכן, הכניסה וההרשמה תיצרו בנושא הבא, עם השמות האלה (או שמות משלכם – באנגלית, באות גדולה):
        
      
          
      היה בתפריטכותבים עכשיו
      
          
      href="index.html"asp-page="/Index"
      
          
      href="page1.html"asp-page="/Site/Page1"
      
          
      href="login.html"asp-page="/Site/Login"
      
        
      
        גם בשם האתר (navbar-brand) כותבים asp-page="/Index" במקום href.
      2. 
      
    2. הוסיפו לרשימת הקישורים, לפני </ul>, קישור לדף "אודות":
        
      <li class="nav-item"><a class="nav-link" asp-page="/Site/About">אודות</a></li>

      3. 
      
    3. שמרו והריצו. בדף הבית לחצו בתפריט על "אודות", ומשם על שם האתר – חזרה לדף הבית.
      4. 
      
    4. בדף "אודות" לחצו Ctrl+U וחפשו (Ctrl+F) Site/About: מצאתם href="/Site/About" – ואף asp-page? חפשו גם Img – ב-src כתוב /Img/… ואין שם ~ בכלל.
      5. 
    
    
    
    בתפריט מופיע "אודות", והלחיצה פותחת את הכתובת שמסתיימת ב-/Site/About עם הדף שלכם. לחיצה על שם האתר מחזירה לדף הבית. הקישורים לדפים שעוד לא יצרתם (Page1, Login) עדיין לא מובילים לשום מקום – ב-Ctrl+U כתוב בהם href="". הם יתחילו לעבוד ברגע שתיצרו את הדפים, בנושא הבא.
    
    
    
  
    
  
    
    
    🎯 הבנתם את כל מה שלמדתם עד עכשיו?
    
    
    
  
    

    



    
  
    
    
    ⚠ מדביקים את כל הדף?
    
    
    עכשיו מעבירים את דפי ה-HTML שלכם לדפי Razor. הנה הטעות הכי נפוצה בשלב הזה:
    
    
    
    
    
      
    ✘ הדבקתי את כל login.html
    
      
    ✔ הדבקתי רק את התוכן
    
    
    
    
    ב-Ctrl+U של הדף השבור – שתי תגיות html:
    
    
    התבנית כבר נותנת לכל דף html, head, body, תפריט, container ו-script. כשמדביקים דף שלם, הכול מגיע פעמיים: שני תפריטים, ודף שלם בתוך המקום של RenderBody. לכן מדף HTML מעתיקים רק את התוכן – בשלב הבא בדיוק איך.
    
  
    

  
    
    
    המתכון: מדף HTML לדף Razor
    
    
    ככה מעבירים כל דף. הנה login.html משיעורים 4–5 – עברו על ארבעת הצעדים:
    
    
    
    
    
      
    wwwroot/HTML/login.html – הדף הישן
    
      
    Pages/Site/Login.cshtml – הדף החדש
    
    
    
    
    
    
    💡 טופס עם method="get" ממשיך לעבוד גם בדף Razor: הנתונים נשלחים לאותו דף, ומופיעים בכתובת. נסו בצעד 4. עם post נעבוד בהמשך השנה, כשתכתבו קוד בקובץ cs.
    
  
    

  
    
    
    💻 עכשיו אצלכם ב-Visual Studio
    
    
    מעבירים שני דפים, לפי המתכון: דף התוכן ודף הכניסה. כל השאר – בצעד הפרויקט, בסוף השיעור.
    
    
      
      
    1. דף התוכן: קליק ימני על Site ‏←‏ Add ‏←‏ Razor Page... ‏←‏ Razor Page - Empty, בשם Page1 (השם שכתבתם בתפריט). השאירו את @page ו-@model, ובמקום הבלוק הריק כתבו כותרת: @{ ViewData["Title"] = "..."; }
      2. 
      
    2. פתחו את page1.html. העתיקו רק את מה שבתוך body – בלי ה-nav, בלי ה-div של container (את מה שבתוכו – כן) ובלי שורת ה-script – והדביקו ב-Page1.cshtml, מתחת לכותרת.
      3. 
      
    3. בדף החדש: כל ../Img/ ‏←‏ ~/Img/. וקישור לדף אחר באתר: href="x.html" ‏←‏ asp-page="/Site/X" – חוץ מ-index.html, שהופך ל-asp-page="/Index" (דף הבית). שמרו, הריצו ולחצו בתפריט על הקישור לדף.
      4. 
      
    4. דף הכניסה: אותו דבר ל-login.html, בדף בשם Login. בדקו: מלאו את הטופס ולחצו "כניסה".
      5. 
      
    5. את קובצי ה-HTML הישנים השאירו בינתיים – הם לא מפריעים, והם הגיבוי שלכם.
      6. 
    
    
    
    הקישורים בתפריט לדף התוכן ולכניסה פותחים את /Site/Page1 ואת /Site/Login – בלי סיומת – ובכל דף יש תפריט אחד, התמונות מופיעות ובלשונית הכותרת של הדף. אחרי "כניסה" הכתובת מסתיימת בערך כך: /Site/Login?userName=dana&password=1234 (עם מה שהקלדתם).

    🛠 נסו עכשיו: מתקנים דף Razor
    
    
    זה About.cshtml – אבל מישהו הדביק בו דף HTML שלם. תקנו אותו לפי המשימות. בתצוגה רואים את הדף בתוך התבנית, כמו בשרת אמיתי (המדריך מדמה את השרת). כשמשימה מצליחה – היא נצבעת בירוק ✔. תקועים? בכל משימה יש רמזים, ובסוף גם פתרון.
    
    
    
  
    

  
    
    
    🧩 צעד בפרויקט – לקראת הגשה 1
    
    
    
      האתר שלכם – כולו ב-Razor, בתבנית אחת. שני דפים כבר עברו (בשלב 💻). עכשיו כל השאר, באותה דרך:
      
      
        
    1. register.html ו-recover.html ‏←‏ דפים Register ו-Recover ב-Pages/Site, וכל דף תוכן נוסף שיש לכם.
      2. 
        
    2. דף הנחיתה: פתחו את Pages/Index.cshtml (הוא נפתח בכתובת /). השאירו את @page ו-@model IndexModel, החליפו את "Home page" בכותרת שלכם, ואת כל ה-div של "Welcome" – בתוכן של index.html (בלי nav ו-script).
      3. 
        
    3. בתפריט ב-_Layout – קישור asp-page לכל דף. הוספתם דף? מוסיפים לו קישור רק כאן.
      4. 
        
    4. בכל דף: @page ו-@model למעלה, כותרת עם ViewData, תמונות עם ~/Img/…, טפסים עם method="get" – ובלי html, head, body, nav ו-script.
      5. 
        
    5. בדיקה: עברו על כל הקישורים – גם ברוחב טלפון (F12, ואז Ctrl+Shift+M). בכל דף: תפריט אחד, תמונות, כותרת בלשונית, ובלי שגיאה אדומה ב-Console.
      6.

    📄 דף סיכום: כל השיעור במסך אחד

    דף Razor
    
        
      
          
    • שני קבצים: About.cshtml (כאן כותבים) ו-About.cshtml.cs (קוד השרת).
      • 
          
    • בראש הדף: @page ו-@model – לא מוחקים.
      • 
          
    • @ = מכאן C#. השרת מריץ, והדפדפן מקבל רק את התוצאה.
      • 
          
    • בלוק פקודות: @{ … } · כותרת: ViewData["Title"] = "אודות";
      • 
          
    • התו @ עצמו בטקסט: @@ · הערה שלא נשלחת: @* … *@
