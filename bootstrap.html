    Bootstrap – עיצוב שמישהו כבר כתב בשבילכם

    Bootstrap היא ספרייה (library) – אוסף מוכן של אלפי כללי CSS, ועוד קצת JavaScript לדברים שזזים (כמו תפריט שנפתח). אתם לא כותבים את הכללים – רק מוסיפים לתגיות שמות של class, ו-Bootstrap כבר יודע איך לעצב אותן.

    הנה אותו HTML בדיוק, פעמיים. בקוד אין אף שורת CSS שלנו – רק class-ים. ההבדל היחיד: בצד אחד הדף מחובר לקובץ של Bootstrap.

    
    
    
    
    בשיעור 3 המצאתם שם של class (כמו sale) וכתבתם לו כלל CSS. עם Bootstrap החלק השני כבר עשוי: מישהו כתב אלפי כללים, ואתם רק מלבישים את השמות על התגיות. ממש כמו ב-C#: אתם כותבים Console.WriteLine בלי לכתוב בעצמכם איך היא עובדת – מישהו כבר כתב אותה בספרייה.
    
    
    ככה, בערך, נראה אחד הכללים בתוך הקובץ של Bootstrap (בגרסה מקוצרת):
    
    
    
    
      
      
    • קוד פתוח (open source) – חינם, וכל אחד יכול להשתמש בו ולראות איך הוא כתוב.
      • 
      
    • נכתב במקור על ידי מפתחים בטוויטר (2011), והיום זו אחת מספריות העיצוב הנפוצות בעולם.
      • 
      
    • היתרון הגדול: אתר שבנוי עם Bootstrap מתאים את עצמו לגודל המסך – מחשב, טאבלט וטלפון. לזה קוראים עיצוב רספונסיבי (responsive – "מגיב" לגודל המסך).
      • 
    
    
    
    💡 הבית של Bootstrap הוא האתר getbootstrap.com. יש בו הסברים ודוגמאות לכל class. נשתמש בו לאורך השיעור.
    
  
    

    



    
  
    
    
    שלוש שורות בכל דף

    שורהאיפהמה היא עושה
    
      
    שורת ה-metaב-headאומרת לטלפון להציג את הדף ברוחב האמיתי שלו. נבין אותה בעוד כמה שלבים.
    
      
    link לקובץ ה-CSSב-headמחברת את כל הכללים של Bootstrap – בדיוק כמו ה-link לקובץ העיצוב משיעור 3 (בדף התרגול זה היה style.css, ובאתר שלכם – site-style.css).
    
      
    script לקובץ ה-JSבסוף ה-body, לפני </body>מחברת את קוד ה-JavaScript של Bootstrap – הוא מפעיל דברים שזזים, כמו תפריט שנפתח בלחיצה.
    
    
    
    
    שתי שורות ב-head ושורה אחת בסוף ה-body – וזהו. כל ה-class-ים של Bootstrap זמינים עכשיו בדף. למה ה-script בסוף? כי קודם הדפדפן מציג את התוכן, ורק אחר כך טוען את הקוד ש"מפעיל" אותו – כך הדף מופיע מהר יותר.
    
    
    💡 במצגת השלב הזה נקרא "התקנה". בפועל לא מתקינים כלום – רק מקשרים לקבצים, כמו שקישרתם לקובץ CSS.
    
    
    🚀 להעמקה: למה דווקא bundle?
      
    בתיקייה js של Bootstrap יש כמה קבצים. bundle פירושו "חבילה": בקובץ bootstrap.bundle.min.js ארוז גם הקוד של Bootstrap וגם ספרייה קטנה נוספת בשם Popper, שיודעת לחשב איפה להציג חלונית קופצת – למשל רשימה נפתחת (dropdown) או בועת הסבר (tooltip) – כך שלא תיחתך בקצה המסך.
    
      
    הקובץ bootstrap.min.js (בלי bundle) הוא בלי Popper. לכן הכי פשוט לקשר תמיד ל-bundle – וכל הרכיבים יעבדו. אפשר לקרוא עוד ב-התיעוד של Bootstrap (באנגלית).

    דף בעברית: dir וקובץ RTL
    
    
    עברית נכתבת מימין לשמאל – RTL (right to left). בדף בעברית צריך שני דברים:
    
    
      
      
    1. בתגית html: dir="rtl" (כיוון: מימין לשמאל) ו-lang="he" (השפה: עברית – עוזר לקוראי מסך ולבדיקת איות).
      2. 
      
    2. לקשר לקובץ המיוחד bootstrap.rtl.min.css – הוא נמצא באותה תיקייה בדיוק, ליד הקובץ הרגיל.
      3. 
    
    
    
    מה קורה אם שמים dir="rtl" אבל מקשרים לקובץ הרגיל? הנה אותו טופס קטן, פעמיים. את ה-class-ים של הטופס נכיר בהמשך – עכשיו הסתכלו רק איפה החץ של הרשימה ואיפה תיבת הסימון:
    
    
    
    
    
    
    הקובץ הרגיל של Bootstrap "חושב משמאל לימין": הוא שם את החץ של הרשימה בצד ימין – בדיוק על הטקסט העברי – ואת תיבת הסימון בצד שמאל, רחוק מהמילים שלה. קובץ ה-RTL הופך את כל הצדדים. מעכשיו, בכל דף בעברית: bootstrap.rtl.min.css.
    
    
    💡 במצגת הקישור להסבר על RTL מוביל לגרסה 5.2 של האתר. הדף העדכני: getbootstrap.com/docs/5.3/getting-started/rtl
    
  
    

  
    
    
    שורת ה-viewport: מה היא עושה?
    
    
    נשארה השורה הראשונה בתבנית:
    
    
    
    
    כדי להבין אותה, צריך לדעת משהו מפתיע על טלפונים.
    
    
    
    
    
    
    
    
    טלפונים עדיין מכבדים אתרים ישנים, שנבנו רק למחשב. לכן, כשאין שורת viewport, הטלפון מעמיד פנים שהמסך שלו רחב (בערך 980 פיקסלים), בונה את הדף ברוחב הזה – ואז מקטין הכול כדי שייכנס. התוצאה: טקסט זעיר, וצריך לעשות זום עם האצבעות. השורה width=device-width אומרת: "הרוחב שלי הוא הרוחב האמיתי של המכשיר". רק אז Bootstrap יכול לסדר את הדף בשבילו.
    
    
    
    🐢 רוצים הסבר לאט יותר?
      
    דמיינו שמישהו שולח לכם פוסטר ענק, ברוחב של מטר. יש שתי דרכים להראות אותו בטלפון:
    
      
      
        
    1. להקטין את כל הפוסטר כדי שייכנס למסך. רואים הכול – אבל האותיות קטנות מדי לקריאה. זה מה שהטלפון עושה בלי שורת viewport.
      2. 
        
    2. לסדר את התוכן מחדש ברוחב של הטלפון: אותו תוכן, באותיות רגילות, אחד מתחת לשני. זה מה שקורה עם שורת viewport – ו-Bootstrap הוא זה שמסדר.
      3. 
      
    
      
    בשפת הקוד: width=device-width = "רוחב הדף = רוחב המכשיר". initial-scale=1 = "בלי זום בהתחלה".
    
    
    
    
    💡 על ההדמיה: מסגרת בתוך דף לא מושפעת משורת viewport, ולכן בנינו כאן הדמיה נאמנה למה שטלפון אמיתי עושה. רוצים לבדוק דף בגודל של טלפון בדפדפן אמיתי? F12 ‏←‏ סמל הטלפון (Ctrl+Shift+M) – כך תבדקו מעכשיו כל דף שלכם. במצגת יש גם קישור להדגמה באתר W3Schools.
    
    
    🥚 תפסתם את המסך ברוחב המדויק! ההודעה הזו מופיעה רק כשהחלון ברוחב 700 עד 760 פיקסלים – כלל CSS שפועל רק בטווח רוחב מסוים. בדיוק ככה Bootstrap בנוי בפנים. הקוד הסודי: BREAKPOINT

    2. פתחו את page1.html (בתיקייה HTML). בשורה של התגית html ודאו שכתוב lang="he" dir="rtl" (כמו בשיעור 2).
      3. 
      
    3. בתוך ה-head, מיד אחרי השורה של meta charset, הדביקו את שתי השורות האלה. הן חייבות להיות מעל השורה של site-style.css שכבר יש לכם משיעור 3: קודם Bootstrap, ואחריו העיצוב שלכם – כך הכללים שלכם מנצחים. (למה? בנושא "משלכם + התיעוד".)

    6. עשו את צעדים 2–4 גם בדף הנחיתה index.html – אותן שלוש שורות, באותם מקומות. כך שני הדפים מוכנים לתפריט המשותף שתבנו בנושא "רכיבים מוכנים".

    container, row, col – שלוש קופסאות
    
    
    הדרך של Bootstrap לסדר דף נקראת גריד (Grid – רשת). היא בנויה משלוש קופסאות, אחת בתוך השנייה:
    
    
      
      
    • container – העוטף החיצוני. ממרכז את התוכן ושומר שהוא לא יימרח על כל רוחב של מסך ענק.
      • 
      
    • row – שורה.
      • 
      
    • col – עמודה בתוך השורה (column).
      • 
    
    
    
    הוסיפו קופסה אחרי קופסה, ושימו לב מה משתנה בכל פעם:
    
    
    
    
    
    
    
    
    הצבעים והקווים – CSS קטן שהוספנו רק כדי שתראו את הקופסאות: כחול מקווקו = container, ירוק מקווקו = row.
    
    
    
    
    זוכרים את הטבלאות משיעור 4? row הוא כמו שורה בטבלה (tr), ו-col הוא כמו תא (td). ההבדל הגדול: טבלה תמיד נשארת טבלה, וגריד יודע להסתדר מחדש בטלפון. עוד מעט תראו איך.
    
  
    

  
    
    
    12 חלקים בכל שורה
    
    
    כל שורה מחולקת ל-12 חלקים שווים. המספר אחרי col- אומר כמה חלקים העמודה תופסת: col-6 = 6 מתוך 12 = חצי. col-4 = שליש. col-3 = רבע. ו-col בלי מספר = כל העמודות מתחלקות שווה בשווה.
    
    
    
    
    
    
    
    
    
    
    הסרגל האפור למעלה (1 עד 12) – רק להמחשה, כדי לספור חלקים.
    
    
    
    
    
    סכום העמודות בשורה גדול מ-12 (למשל col-8 ועוד col-6): העמודה שלא נכנסת יורדת לשורה הבאה. אין הודעת שגיאה – רק סידור מוזר. בודקים שהמספרים בכל שורה מסתכמים ב-12 לכל היותר.
    
    
    🐢 רוצים הסבר לאט יותר?
      
    חשבו על פיצה של פיצה דני, חתוכה ל-12 משולשים. השורה (row) היא הפיצה, וכל עמודה מקבלת כמה משולשים:
    
      
      
        
    • col-6 = 6 משולשים = חצי פיצה.
      • 
        
    • col-4 = 4 משולשים = שליש. שלוש עמודות כאלה = פיצה שלמה.
      • 
        
    • col-8 ועוד col-6 = 14 משולשים – יותר ממה שיש בפיצה אחת! אז העמודה השנייה "עוברת" לפיצה הבאה, כלומר לשורה הבאה.
      • 
      
    
      
    ולמה דווקא 12? כי 12 מתחלק יפה ב-2, 3, 4 ו-6 – אפשר לחלק לחצאים, לשלישים ולרבעים.
    
    
    
    
    💡 אפשר לשים row חדש בתוך עמודה (במצגת: "גריד מכונן" – הכוונה למקונן, nested). זה עובד, אבל העמודות נהיות צרות מאוד – בדרך כלל לא כדאי.
    
  
    

  
    
    
    איך זה נראה בטלפון?
    
    
    שלוש מנות, כל אחת col-4. במחשב זה נראה מצוין. עכשיו בחרו 📱 טלפון:
    
    
    
    
    
    
    בטלפון ברוחב 360, כל עמודה מקבלת שליש – בערך 120 פיקסלים. הטקסט נמעך לשורות קצרות, וקשה לקרוא. מה היינו רוצים? סידור שמתאים לכל מסך – ולא אותו סידור צפוף בכולם. לזה בדיוק נועדו נקודות השבירה – בשלב הבא.
    
    
    💡 על כפתורי המכשיר: המסגרת מקבלת בדיוק את הרוחב שבחרתם, ו-Bootstrap מגיב אליה כמו למסך אמיתי. כשהמסך שלכם צר מדי – ההדמיה מוקטנת כדי להיכנס, וכתוב מתחתיה בכמה.
    
  
    

  
    
    
    נקודות שבירה: col-md-4

    🐢 רוצים הסבר לאט יותר?
      
    כש-Bootstrap פוגש מנה עם col-md-4, הוא שואל שאלה אחת: "המסך רחב לפחות 768 פיקסלים?"
    
      
      
        
    • כן (טאבלט, מחשב) – המנה מקבלת 4 משולשים מתוך 12. שלוש מנות = שורה מלאה.
      • 
        
    • לא (טלפון) – ה-class "לא נדלק", והמנה מתנהגת כמו div רגיל: תופסת את כל הרוחב.
      • 
      
    
      
    הכלל לזכור: class עם שם של נקודת שבירה פועל מהרוחב הזה ומעלה. class בלי שם (כמו col-4) פועל תמיד, בכל רוחב.
    
    
    
  
    

  
    
    
    🔬 מעבדת גריד
    
    
    בחרו class לשלוש המנות, ואז עברו בין המכשירים. מתחת להדמיה כתוב כמה מנות יש בכל שורה.
    
    
    ה-class של כל מנה:
    
    
    
    
    
    
    
    
    
      🎯 אתגר: איזה class נותן מנה אחת בשורה בטלפון, שתיים בטלפון לרוחב ובטאבלט, ושלוש במחשב? נסו את האפשרויות ובדקו בכל מכשיר.
    
    
    
    הפתרון
    col-sm-6 col-lg-4. אפשר לתת לתגית כמה class-ים עם נקודות שבירה שונות: מ-sm ומעלה חצי (6), ומ-lg ומעלה שליש (4). מתחת ל-sm – שורה שלמה.
    
  
    

  
    
    
    row-cols: כמה בשורה, לכל מסך
    
    
    יש דרך קצרה יותר: במקום לכתוב class על כל עמודה, כותבים על השורה כמה עמודות יהיו בה. העמודות עצמן מקבלות רק col.
    
    
    
    
    
    
    
    
    קראו את ה-class-ים של השורה משמאל לימין, כמו שלושה כללים:
      
    • row-cols-1 – תמיד: עמודה אחת בשורה (טלפון).
      
    • row-cols-sm-2 – מ-sm ומעלה: שתיים בשורה (טלפון לרוחב).
      
    • row-cols-md-4 – מ-md ומעלה: ארבע בשורה (טאבלט ומחשב).
      
    כל כלל "דורס" את הקודם כשהמסך מספיק רחב. זה בדיוק הסידור שבמצגת.
    
    
    💡 ומה זה g-3? g = gutter – רווח בין העמודות, גם לרוחב וגם לגובה. המספר בין 0 (צמוד) ל-5 (הכי רחוק).
    
    
    💡 ותמונה בתוך עמודה? תמונה רחבה לא מתכווצת לבד – היא עלולה לבלוט מחוץ לעמודה. ה-class img-fluid ("תמונה גמישה") שומר שהתמונה אף פעם לא תהיה רחבה מהעמודה שלה, ומתכווצת יחד איתה: <img src="../Img/pizza.jpg" alt="פיצה" class="img-fluid" />
    
    
    🚀 להעמקה: מה כתוב בתוך Bootstrap?
      
    מאחורי כל class עם נקודת שבירה מסתתר כלל CSS מיוחד בשם media query (בערך: "שאלה על המסך"). הוא אומר לדפדפן: "את הכללים שבפנים – החילו רק כשהמסך רחב לפחות כך וכך". ככה, בקיצור, כתוב col-md-4 בתוך הקובץ של Bootstrap:
    
      
    @media (min-width: 768px) {
    .col-md-4 {
        flex: 0 0 auto;      /* part of the row layout */
        width: 33.33333333%; /* 4 of 12 */
    }
}

    
      
    מתחת ל-768 הכלל פשוט לא קיים – ולכן העמודה תופסת שורה שלמה. אותו כלי זמין גם לכם: אפשר לכתוב media query ב-site-style.css, למשל כדי להקטין כותרת רק בטלפון. קראו עוד ב-MDN: Using media queries (באנגלית).

    🚀 להעמקה: מה זה בכלל data-bs-toggle?
      
    מאפיין (attribute) שהשם שלו מתחיל ב-data- הוא מאפיין שממציאים: לדפדפן עצמו אין מה לעשות איתו, אבל קוד JavaScript יכול לקרוא אותו. כך Bootstrap עובד: הקוד שלו מקשיב ללחיצות בדף, וכשלוחצים על תגית עם data-bs-toggle (bs = Bootstrap), הוא קורא את המאפיינים שלה ופועל לפיהם – data-bs-toggle="collapse" = "בלחיצה: קפלו ופתחו", ו-data-bs-target = "את מי".
    
      
    התוצאה: אתם מפעילים JavaScript בלי לכתוב אף שורת JavaScript. אפשר לקרוא עוד ב-MDN: data-* (באנגלית).
    
    
    
    
    
  
    

  
    
    
    sticky-top: תפריט שנשאר למעלה
    
    
    מוסיפים לשורה הראשונה של התפריט את ה-class sticky-top ("דבוק למעלה"), והתפריט נשאר בראש המסך גם כשגוללים. בחרו, ואז גללו בתוך המסגרת:
    
    
    
    
    
    
    
    
    בלי sticky-top התפריט נגלל למעלה ונעלם עם שאר הדף. עם sticky-top הוא "נדבק" לראש המסך – והקישורים תמיד זמינים, גם בתחתית של תפריט ארוך.

    CSS משלכם מעל Bootstrap
    
    
    Bootstrap לא מחליף את קובץ ה-CSS שלכם – הוא מתחתיו. מקשרים את שניהם, והסדר חשוב: קודם Bootstrap, ואחריו site-style.css שלכם. בדקו מה קורה כשהסדר הפוך:

    💡 הדרך הכי בטוחה לעיצוב ייחודי: להמציא class משלכם (כמו price) ולשים אותו ליד ה-class-ים של Bootstrap: class="card-text price". לתגית מותר לקבל כמה class-ים, מופרדים ברווח.
