    ה-Console: איפה JavaScript "מדבר"

    את F12 אתם כבר מכירים משיעורי HTML – שם ראיתם שגיאות אדומות כמו 404. בלשונית Console גם JavaScript כותב: הודעות שהוא רוצה להראות לכם, ושגיאות. הפקודה שכותבת ל-Console: console.log(…). כאן בארגז יש Console משלכם.

    כל מה שבין מרכאות הוא טקסט – JavaScript מציג אותו בדיוק כמו שהוא, גם אם כתוב בו 2 + 3. מה שאין בו מרכאות הוא קוד – JavaScript מבצע אותו. ולכן ב-🔨 הראשון, שלום בלי מרכאות נראה לו כמו שם של משתנה (על משתנים – מיד).
    ב-C# כתבתם Console.WriteLine("…"). כאן: console.log("…") – c קטנה, ואחרי log אין Line. ב-JavaScript אותיות גדולות וקטנות הן שני דברים שונים, בדיוק כמו ב-C#.

    איפה כותבים JavaScript? בתגית script – ועדיף בקובץ נפרד

    JavaScript נכנסת לדף HTML דרך התגית <script>. יש שתי דרכים, ובדיוק כמו ב-CSS – קובץ נפרד עדיף:

    א. כותבים בתוך הדף – טוב לניסוי קטן

    <body>
  <h1>פיצה דני</h1>
  <script>
    console.log("שלום");
  </script>
</body>

    ב. בקובץ js נפרד – כך נעבוד

    <body>
  <h1>פיצה דני</h1>
  <script src="../js/practice.js"></script>
</body>

    והקובץ wwwroot/js/practice.js מכיל רק: console.log("שלום");

    • למה קובץ נפרד? אותו קוד משמש כמה דפים, הדף נשאר נקי (HTML בלבד), ומתקנים במקום אחד – כמו קובץ ה-css של האתר.
    • איפה בדף? בסוף ה-body, ממש לפני </body>. הדפדפן קורא מלמעלה למטה, ותגיות שמתחת לסקריפט עדיין לא קיימות כשהוא רץ. וכשנצטרך את זה (בשיעור 3) ההרגל הנכון כבר יהיה אצלכם.
    • הנתיב: דפי ה-HTML שלכם ב-wwwroot/HTML, והקבצים בתיקייה חדשה, wwwroot/js. לכן ../js/practice.js – "עלו תיקייה אחת, וממנה אל js", כמו ../Img בתמונות.
    גם כשיש src וה-script ריק בפנים – חייבים תגית סוגרת: <script src="…"></script>. הצורה <script src="…" /> לא עובדת: הדפדפן "יאכל" את שאר הדף.
    בדף Razor הנתיב הוא ~/js/practice.js – כמו ~/Img/… (שיעור 6). את זה נעשה בפרויקט שלכם בסוף השיעור.

    שלוש דרכים להציג משהו

    JavaScript יכולה להראות דברים בשלושה מקומות. הקוד הזה עושה את שלושתם – בשורה אחת לכל מקום:

    console.log כותבת ל-Console: מקום למפתחים (אתם!), הגולש לא רואה אותו. alert פותחת חלון, והקוד עומד וממתין עד שלוחצים אישור. document.write כותבת לתוך הדף, ומותר לכתוב בה גם תגיות HTML – כמו <h2>.
    בתרגילים של השיעור (ובסרטון) תשתמשו הרבה ב-document.write, כדי לראות את התוצאה בדף עצמו, וב-console.log כשרוצים לבדוק משהו בלי להפריע לגולש.
    רוצים שורה חדשה בין שני document.write? כותבים בסוף <br> – כי דף HTML לא יורד שורה לבד. (document.writeln, שמופיעה בסרטון, לא עושה את זה בדף: היא רק יורדת שורה בקוד המקור.)

    🔨 document.write: למה היא "רעה" – ומתי

    לפני שנסתמך עליה, בדיקה אחת. בדף יש כפתור (איך הוא עובד – בשיעור הבא), ובלחיצה עליו הפקודה document.write כותבת משפט. בדף שכבר נטען.

    קודם ▶ הריצו – הדף נטען בחלון. ואז לחצו על הכפתור שבתוכו.

    document.write שרצה בזמן שהדף נטען – מוסיפה טקסט במקום שבו נמצא הסקריפט. אבל אחרי שהדף נטען, קריאה אליה מחליפה את הדף כולו בדף חדש – והדף הקודם נעלם. לכן היא טובה לתרגילים ראשונים, ולא לדף אמיתי.
    בסרטון תראו אותה, וכך נתרגל גם אנחנו. בשיעורים הבאים נכתוב לתוך הדף בדרך אחרת, שמשנה רק חלק ממנו. עד היום: document.write – מהשיעור שבו נכיר אותה: innerHTML.

    משתנה: קופסה עם שם – בלי לכתוב מה הסוג

    משתנה שומר ערך בשם, כדי להשתמש בו שוב. מגדירים אותו עם let, ואז שם, = וערך. בסוף כל פקודה – ;. ועוד שני דברים בקוד שלמטה: console.log מדפיס כמה ערכים אם מפרידים ביניהם בפסיק, ו-typeof x אומר מאיזה סוג הערך של x.

    ב-C# כתבתם int price = 45; – עם סוג. ב-JavaScript אין סוג בהגדרה: let price = 45;, והמחשב מבין לבד. וגם אפשר, בהמשך, לשים במשתנה ערך מסוג אחר – מה שב-C# היה שגיאה.
    הפקודה typeof אומרת מאיזה סוג הערך. ארבעה סוגים להכיר:
    סוגדוגמהב-C# זה בערך
    number45 · 3.15int ו-double – שניהם סוג אחד
    string"מרגריטה"string
    booleantrue · falsebool
    undefinedמשתנה שהוגדר בלי ערך: let x;(ב-C# אי אפשר להשתמש במשתנה שלא קיבל ערך)
    📼 בסרטון תראו var, ואפילו משתנים בלי הגדרה בכלל. var עושה כמעט אותו דבר, אבל מרשה דברים מבלבלים: להגדיר את אותו שם פעמיים, או להשתמש בו לפני שהגדרתם. לכן אצלנו תמיד let – ומי שכותב var לא מקלקל כלום, זה אותו רעיון. ומשתנה בלי הגדרה (x = 5)? JavaScript מרשה, אבל שגיאת הקלדה במקום אחר תיצור משתנה חדש בשקט. תמיד מגדירים.

    + מחבר מספרים – ומדביק טקסטים

    כמו ב-C#: + בין שני מספרים מחבר; בין שני טקסטים – מדביק אותם (מחרוזות, string). אבל מה קורה כשהמספר הוא בעצם טקסט, כי הוא בין מרכאות? לפני שמריצים:

    "5" + "3" – שני טקסטים, ולכן מדביקים: 53. "5" * "3" – לכפל אין משמעות בטקסט, אז JavaScript ממירה אותם למספרים ומחשבת: 15. הכלל: + עם טקסט = הדבקה; - * / = חישוב (ממירים למספרים). אחרי שנקרא קלט מהמשתמש, הכלל הזה יציל אתכם מבאג.
    ובלחיצה על "מכפילים טקסט" – NaN היא לא שגיאה אדומה: JavaScript לא עוצרת. היא מחזירה ערך ש"אינו מספר", והחישוב ממשיך – ולכן לא תראו אותו אלא אם תבדקו.
    ב-C#, "5" * "3" לא מתקמפל בכלל. JavaScript מנסה "להבין" – וזה נוח, ומסוכן.

    קלט מהגולש: prompt מחזיר טקסט

    הפקודה prompt("שאלה") פותחת חלון עם שדה, ומחזירה את מה שהגולש הקליד. גם אם הקליד מספר – מה שחוזר הוא טקסט. כדי לחשב איתו, ממירים:

    פקודהמחזירה
    parseInt("5")5 – מספר שלם
    parseFloat("10.33")10.33 – גם עם נקודה עשרונית
    parseInt("2.5")2 – חותך את מה שאחרי הנקודה, בלי שגיאה (לעשרוניים – parseFloat)
    parseInt("פיצה")NaN – אי אפשר להפוך למספר

    כשיקפצו החלונות: כתבו 5, ואחרי זה 3.

    הקוד הראשון מחבר שני טקסטים: "5" + "3" = 53. כשעוטפים כל prompt ב-parseInt, מקבלים מספרים – ו-+ מחשב.
    🔗 ב-C# כתבתם int.Parse(Console.ReadLine()) – אותו רעיון, בשם אחר.
    לחצו "ביטול" בחלון? prompt מחזיר null. ו-parseInt(null) הוא NaN. כשכותבים תוכנית אמיתית, צריך לבדוק את זה – לא היום.

    if ו-else: התוכנית מחליטה

    עד עכשיו כל שורה רצה, בלי לשאול. עם if התוכנית בודקת תנאי, ומריצה חלק אחד בלבד מהקוד. בפיצה דני: משלוח חינם מ-100 שקלים.

    אותו if (…) { … } else { … } שאתם מכירים מ-C#, וגם else if נכתב אותו דבר. הבדל אחד גדול – בקרוב.
    התנאי total >= 100 נבדק: 100 גדול או שווה ל-100 – אמת, ולכן רץ הבלוק הראשון. ה-else רץ רק כשהתנאי שקר. תמיד רץ בדיוק אחד מהחלקים. את הסוגריים סביב התנאי ואת הסוגריים המסולסלים אי אפשר לשכוח – נסו 🔨.

    השוואות: === ולא ==

    תנאי הוא בדרך כלל השוואה, והתוצאה שלה היא true או false. הנה כמה מהן:

    === שואלת: "אותו ערך ומאותו סוג?" – ולכן "5" === 5 היא false: טקסט לא שווה למספר. == (שני סימני שוויון) ממירה סוגים לפני ההשוואה, ולכן "5" == 5 היא true – נוח, ומבלבל, ועלולה להסתיר באגים.
    צריךכותבים
    שווה / לא שווה=== · !==
    גדול / קטן> · <
    גדול או שווה / קטן או שווה>= · <=
    📼 בסרטון תראו ==, והוא עובד. אצלנו תמיד === – זה בדיוק מה ש-== עושה ב-C#: משווה גם סוג. כך אין הפתעות.
    גם "10" > "9" מפתיעה: שני טקסטים מושווים לפי סדר אלפביתי (התו "1" לפני "9"), ולכן התשובה false. אחרי prompt – קודם parseInt, ורק אז משווים. (לחצו 🔨 לראות.)

    וגם, או, לא: && || !

    תנאי אחד לא תמיד מספיק. מבצע סטודנטים בפיצה דני: סטודנט וגם בין 14:00 ל-17:00.

    פעולהכותביםאמת כש…
    וגם&&שני הצדדים אמת
    או||לפחות צד אחד אמת
    לא!הערך הפוך: !true הוא false
    אותם סימנים בדיוק כמו ב-C#. ובדיוק כמו שם: כשמשלבים && ו-|| – סוגריים, כדי שיהיה ברור מה נבדק קודם.
    כשמשלבים כמה תנאים עם &&, כולם חייבים להיות אמת. כאן isStudent הוא false – ולכן התנאי כולו שקר, גם אם השעה מתאימה.

    ⚠ שני תנאים שנראים נכון – ולא עובדים

    הטעויות הכי קשות הן כאלה בלי שגיאה אדומה: הקוד רץ, ועושה משהו אחר ממה שרציתם. הנה אחת. במתמטיקה כותבים "14 ≤ שעה ≤ 17", ולכן כתבו ככה:

    JavaScript מחשבת משמאל לימין, צעד אחר צעד: קודם 14 <= hour – אמת. ואז true <= 17, כאשר true הופך למספר 1: 1 <= 17 – אמת! התנאי תמיד נכון. התיקון: כל השוואה לבדה, וביניהן &&: hour >= 14 && hour <= 17.
    והבאג השני, 🔨 "= במקום ===": כתבתם = אחד. זו השמה (שמים 14 ב-hour), לא השוואה – ההשמה מחזירה 14, וזה נחשב "אמת". גם כאן אין שגיאה אדומה, והמשתנה השתנה.
    ב-C#, if (x = 5) לא מתקמפל – התנאי חייב להיות bool. ב-JavaScript הוא מותר – ורץ. אז כשכותבים השוואה – שלוש פעמים =.

    switch: הרבה אפשרויות לאותו משתנה

    כשבודקים אותו משתנה מול כמה ערכים, switch ברור מ-else if ארוך. כל case הוא ערך אפשרי; break אומר "סיימתי, צאו"; ו-default הוא ה-else – כל השאר.

    בלי break, JavaScript "נופלת" אל ה-case הבא ומריצה גם אותו – ואת הבא אחריו – עד הסוף או עד break. לכן שלוש שורות ולא אחת.
    ב-C# השמטת break היא שגיאת קומפילציה, והמחשב מציל אתכם. ב-JavaScript אין שגיאה – ולכן תמיד כותבים break. ה-switch משווה עם ===: "1" ו-1 הם לא אותו case.

    לולאת for: הקוד חוזר – ואנחנו עוקבים אחריו

    רוצים לסכום את המספרים 1 עד 4? אפשר לכתוב ארבע שורות. ומה עם מאה? לולאה מריצה את אותו קוד שוב ושוב. ב-for שלושה חלקים בסוגריים, מופרדים ב-;:

    for (let i = 1; i <= 4; i++) { … }
    1. let i = 1 – התחלה. רצה פעם אחת, לפני הלולאה.

    3. i++ – קידום. רץ אחרי כל סיבוב. i++ זה קיצור של i = i + 1.

    for (let i = 1; i <= 10; i++) {
  // כאן הגוף
}

while (i <= 10) {
  // כאן הגוף

}

    המטלה בקלאסרום היא שבע התוכניות שכתבתם בשלבי 💻 – ארבע על משתנים ותנאים, ושלוש על לולאות. זו מטלת תרגול: בלי ציון, עם משוב לפי מחוון – והגשה חובה. מומלץ לחלק לשלושה ימים, נושא ליום.
    
    
    
  
    

  
    
    
    ✅ בדקו את עצמכם
    
    
    9 שאלות שמחברות את כל השיעור – במצבים שעוד לא ראיתם. טעיתם? ההסבר יגיד למה – ונסו שוב.
    
  
    

  
    
    
    📄 דף סיכום: כל השיעור במסך אחד
    
    
    כל מה שצריך לזכור. אפשר לחזור לכאן בכל זמן, או להדפיס. 
    
    
    
      
    📌 מה מגישים
    
        
     – שבע תוכניות: מכפלה, ברכה, יחס בין מספרים, מחשבון, סכום של 10, ממוצע של 10, וממוצע ציונים עד מספר שלילי. כל תוכנית נבדקה עם שתי דוגמאות וקלט "מוזר"; zip של כל תיקיית הפרויקט, עם ה-sln (כל הפרטים).
    
      
    איפה כותבים
    
        
      
          
    • קובץ wwwroot/js/x.js, וחיבור: <script src="../js/x.js"></script> – בסוף ה-body.
      • 
          
    • תגית סוגרת תמיד. בדף Razor: ~/js/x.js.
      • 
          
    • הערה: // · שינוי בקובץ js ולא רואים? Ctrl+F5.
      • 
        
    
      
    פלט
    
        
      
          
    • console.log(…) – ל-Console (F12), למפתח.
      • 
          
    • alert(…) – חלון קופץ, הקוד ממתין.
      • 
          
    • document.write(…) – בתוך הדף; שורה חדשה: <br>. אחרי טעינת הדף – מוחקת אותו.
      • 
        
    
      
    משתנים וסוגים
    
        
      
          
    • let price = 45; – בלי סוג.
      • 
          
    • סוגים: number, string, boolean, undefined. typeof x אומר איזה.
      • 
          
    • אותיות גדולות וקטנות חשובות. תמיד let (לא var).
      • 
        
    
      
    פלוס, קלט והמרות
    
        
    
          
    "5" + "3"53 – הדבקה
    
          
    "5" * "3"15 – חישוב
    
          
    prompt(…)מחזיר טקסט (null בביטול)
    
          
    parseInt(…)שלם · parseFloat – עשרוני
    
          
    לא מספרNaN – בלי שגיאה אדומה
    
        
    
      
    השוואות ותנאים
    
        
      
          
    • === ו-!== (לא ==) · > < >= <=
      • 
          
    • && וגם · || או · ! לא (וסוגריים כשמשלבים)
      • 
          
    • תחום: x >= 10 && x <= 20 – לא 10 <= x <= 20
      • 
          
    • if · else if · else · switch עם case, break, default
      • 
        
    
      
    לולאות
    
        
    for (let i = 1; i <= 10; i++) {
  sum = sum + i;
}

    
        
      
          
    • התחלה · תנאי (לפני כל סיבוב) · קידום (אחרי).
      • 
          
    • i < 10 – 9 סיבובים. ב-while (ש-i מוגדר מחוץ לה) – אחרי הלולאה i גדול ב-1.
      • 
          
    • צובר (sum) מתחיל ב-0. ממוצע – אחרי הלולאה.
      • 
          
    • עד סימן עצירה: while, קוראים לפני הלולאה ושוב בסוף הסיבוב.
      • 
        
    
      
    🔗 מה שונה מ-C#
    
        
    
          
    הגדרהlet – בלי סוג
    
          
    המרהparseInt
    
          
    if (x = 5)ב-C# שגיאה, כאן רץ
    
          
    break ב-switchב-C# חובה, כאן אפשר לשכוח
    
          
    איפה רץבדפדפן, לא בשרת
    
        
    
      
    הקוד לא עובד? בודקים:
    
        
      
          
    • F12 ‏←‏ Console: שורה אדומה? קראו מה וגם באיזו שורה.
      • 
          
    • שמרתם? Ctrl+F5 בדפדפן. 404 על הקובץ? נתיב.
      • 
          
    • הפלט 53 או NaN? parseInt חסר.
      • 
          
    • תנאי "תמיד נכון"? = במקום ===, או 10 <= x <= 20.
      •
